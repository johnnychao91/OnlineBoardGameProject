# Boardgame · 朋友桌遊室

供朋友透過瀏覽器一起遊玩的線上桌遊平台，程式與部署服務統一命名為 `boardgame`，透過遊戲註冊介面加入不同遊戲，使用 boardgame.io 管理規則與多人狀態。名稱、介面文案與視覺素材均以本專案自己的設計為準。

| 遊戲 | 人數 | 玩法 |
| --- | --- | --- |
| 太空維修站 | 4～8 人 | 隱藏陣營、公開宣稱與檢修設備 |
| 加密通話 | 2～4 人 · 8 歲以上 | 諜報背景的合作遊戲，保持沉默、由小到大傳送數字訊號 |

前端使用 React，遊戲由 Node.js 伺服器裁定；開發環境支援 Windows 與 Linux。正式環境可部署於 Linux 伺服器，由 Apache 提供 HTTPS 反向代理。

公開儲存庫不綁定任何實際網站。文件中的 `example.com` 及其子網域都是示範值；真實網域、IP、憑證與密鑰只保存在主機的私有設定中，不要改回已追蹤的文件或範本。提交前執行 `npm run check:public`，CI 也會檢查。

## 0.8.1 版功能

- 每輪資訊確認與輪末準備下一輪時，牌桌在各玩家名字旁即時顯示「待準備／已準備」，觀戰與復盤也能查看。

- 太空維修站開局由伺服器從實際參與者中隨機選出第一位檢修者，之後依原規則交接。
- 新增設備翻開提示音與「輪到自己檢修」的不同提示音，可切換靜音並記住設定。觀戰可聽翻牌音；復盤不播放即時提示音。

- 干擾者身分、觀戰與結局標示、戰報圖片統一採用紅色。

- 維修模組宣稱選項以全桌尚未翻出的維修模組數與自己的暗牌數兩者較小值為上限，前端及伺服器使用相同限制。

- 太空維修站改用紅色標示反應爐危機，電腦版使用橫向牌桌與側欄；手機維持直向操作。
- 新增「本輪檢修順序」，依實際翻牌先後顯示設備、檢修者及持牌者，玩家、觀戰與復盤皆可查看。
- 每輪最後一張翻開後先保留牌桌，全員按「已看清楚，準備下一輪」才洗牌進入下一輪。直接產生勝負時，結果與最後牌桌保留至少 8 秒，再自動回原等待室。
- 輪末確認適用於更新後開始的新局；已開始的舊局及既有回放保持原規則。

- 等待室及對局畫面顯示觀戰席名單，觀戰者可辨識自己的暱稱；觀戰不計入玩家人數。
- 等待室可直接切換「觀戰」與「參加遊戲」，保留暱稱、邀請與歷史，不用重新加入。改為玩家後須準備，其他玩家的準備狀態保留；房主改為觀戰時自動交接。
- 開局後身分固定，回到等待室才可切換。同一瀏覽器的其他分頁會跟隨同一身分；網路遺失回應時可重試找回切換結果。

- 新增「加密通話」：100 張數字訊號牌、逐級增加的手牌、全隊掩護與須經全員同意的靜默脈衝。
- 不設輪流出牌或公共計時器，傳送由伺服器按收到順序裁定；每輪與失序後須全員同步。網路延遲會影響接收順序，詳細規則見[加密通話](docs/ENCRYPTED_CALL.md)。
- 新遊戲沿用私人邀請、獨立觀戰席、回放分享、公開戰報 PNG、房主中止及原房再開局。合作統計記錄全隊成功／失敗，不把攔截系統算成玩家陣營。

兩款遊戲共用以下房間功能；太空維修站的既有流程保持相容：

- 同一房間可連續遊玩；每局結束自動返回等待室、清除準備狀態，保留成員與邀請連結。各局戰績及回放獨立保存。
- 房主可確認後提前結束本局；中止不計勝敗，也不開放未完成對局的秘密回放。
- 玩家與觀戰者可主動離開，房主離開時管理權交給剩餘玩家。全員離線保留 60 秒重連時間，逾時自動中止並回到等待室。
- 遊戲用語統一為「維修模組」、「檢修」、「維修員」與「干擾者」。

- 太空維修站的身份旁顯示 4～8 人局可能的維修員／干擾者組合；不透露實際未公開陣營。
- 每輪確認資訊後，以數字選項公開宣稱維修模組數量；允許說謊，全員宣稱後開始檢修。
- 第一次點牌公開預選位置，再次點同牌後確認檢修；所有玩家可見預選，觀戰依輪詢更新。
- 已翻開的牌保留於本輪原位，顯示牌種；強化目前檢修者及自己的回合提示。
- 三個房間同時遊玩的整合測試，檢查玩家操作、觀戰權限、持久化、復盤及統計隔離。
- 建房不用選人數；等待室符合所選遊戲的人數範圍且全員準備後，由房主開始，依當時人數配牌。
- 房主可在開局前單次移出其他玩家，立即撤銷舊座位；對方持有效邀請仍可重新加入。開局後名單固定。
- 可自行設定至少 16 字元的開房長密碼，並選擇在自己的瀏覽器記住；成功開房後才儲存，可隨時清除。朋友加入不需要開房密碼。
- 加入時可選參與遊戲或觀戰，等待室內也能互換。觀戰不占玩家席位，進行中就能切換盲視角／上帝視角；同一個人也可能用另一個瀏覽器觀戰，需靠朋友間約定避免透露秘密。
- 首頁提供全站遊戲及陣營勝敗統計，只計完成對局，不以暱稱追蹤個人。
- 有完整歷史的對局，賽後可逐步、自動播放復盤，切換公開資訊或參與者的完整牌面。
- 可分享從選定步驟開始的整局唯讀復盤連結（7 天有效、視角由伺服器鎖定、房主可撤銷）。瀏覽器也可產生 PNG 戰報供下載／手機分享，圖片僅含公開事件、暱稱與進度，即使目前使用上帝視角也不包含秘密牌面。

既有 schema 1 資料與憑證可繼續使用。舊版已開始的對局沒有完整逐步歷史，更新後不會補造回放，也不能建立回放分享；仍可繼續原局，有完整終局結果後納入統計。更新後才從等待室開始的新局會保存完整歷史。

0.3 加入的宣稱、公開預選與固定牌位流程適用於使用該版本之後開始的對局。更早的對局及既有回放保留原規則；資料與遊戲 ID 不需重建。部署更新前先等對局結束，完成後所有人重新整理頁面。

## 開始開發

需要 Node.js 24 LTS、npm 與 Git。先取得專案並安裝相依套件：

```sh
git clone https://github.com/johnnychao91/OnlineBoardGameProject.git boardgame
cd boardgame
npm ci
```

複製環境設定。在 Windows PowerShell 執行：

```powershell
Copy-Item .env.example .env
```

在 Linux 執行：

```sh
cp .env.example .env
```

接著啟動開發環境：

```sh
npm run dev
```

開啟終端機顯示的前端網址，預設為 `http://localhost:5173`。開發指令會一起啟動 Vite 與遊戲伺服器；Vite 將 `/api` 和 `/socket.io` 轉送到 `127.0.0.1:3001`。

建立房間後，把邀請連結傳給朋友。測試多位玩家時，請使用不同瀏覽器或彼此隔離的瀏覽器設定檔，避免共用同一個座位憑證。遠端朋友連線需要依部署文件設定網域與 HTTPS；本機開發預設只監聽本機。

房間身分切換需使用支援 Web Locks 的新版瀏覽器，透過 HTTPS 或本機 `localhost` 開啟，以協調同一瀏覽器的多個分頁。

## 常用指令

| 指令 | 用途 |
| --- | --- |
| `npm run dev` | 同時啟動開發前端與 Node.js 服務 |
| `npm run typecheck` | 檢查 TypeScript 型別 |
| `npm test` | 執行專案測試 |
| `npm run check:public` | 檢查已追蹤檔案是否意外包含實際站點、常見密鑰或私有檔案 |
| `npm run build` | 建置前端與伺服器 |
| `npm start` | 啟動建置後的服務；`NODE_ENV=production` 時另提供 `dist/client` 前端檔案 |

正式環境必須設定 `NODE_ENV=production`、HTTPS 的 `PUBLIC_ORIGIN`，以及至少 16 字元的 `CREATE_ROOM_KEY`。`PUBLIC_ORIGIN` 只能包含協定、主機與選填埠號，不能有路徑、查詢字串或結尾斜線；例如 `https://boardgame.example.com`。設定不符時伺服器會拒絕啟動。可使用隨機長密鑰，或以多個隨機挑選、彼此無關的單字組成長密碼；不要使用公開示範值或可猜出的個人資料。`CREATE_ROOM_KEY` 只限制建立新房間；朋友透過房間邀請加入。正式密碼只修改 Git 外的 `/etc/boardgame.env`，方法見維運手冊。

`HOST` 預設為 `127.0.0.1`，`PORT` 預設為 `3001`。Apache 反向代理部署請保留本機監聽。開發環境若變更服務埠號，需同時調整 Vite 的代理目標。

## 使用範圍與目前邊界

- 人數依遊戲而定：太空維修站 4～8 人、加密通話 2～4 人。開始後不開放新玩家加入，但持有效邀請仍可觀戰。
- 原房再開局需要所有留在房間的玩家重新準備；觀戰不占名額。新的一局使用獨立對局 ID，舊的操作及分享不會指向新局。等待室身分切換也會更新目前對局 ID，但保留其他玩家的準備狀態。
- 入房邀請與回放分享是不同權限。邀請有時效，房主可重設邀請；分享連結不含自己的座位或房主憑證。回放連結只開放發行者選定的視角，房主可撤銷全部已發行的回放連結。
- 玩家與觀戰憑證保留於目前瀏覽器。切換身分會換發憑證並撤銷舊身分，其他分頁跟隨更新；重新整理與短暫斷線可重新同步。目前不提供換裝置、清除瀏覽器資料後的身份恢復服務。
- 觀戰名單僅提供給已加入房間的成員，歷史回放與分享不附帶目前觀戰名單。
- 對局與回放資料寫入 `DATA_DIR`，統計從已完成對局推算，重新整理不會重複累加。伺服器重啟恢復與備份還原仍應依部署文件在目標機器驗收。
- 邀請到期不會刪除房間；目前沒有自動清理舊房間或到期對局的功能。
- 目前以朋友試玩與單機服務為範圍。可同時容納的房間數需要依實際伺服器與網路環境量測。
- 原創名稱與素材可以降低直接複製表現內容的風險，但不是任何用途均無法律風險的保證；新增素材時應保留來源與授權資料。
