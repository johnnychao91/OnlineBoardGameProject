# 房間生命週期與唯讀檢查

自動結束的是「正在進行的對局」，不是刪除整個房間。對局中止後回到原等待室，保留遊戲設定、已登記成員、邀請與歷史；沒有定期刪除舊房間的工作。因此 `rooms.json` 中有房間、`matches` 中有舊檔，均不表示它仍在遊戲中。

## 全員離開後

- 虛擬玩家不建立線上連線或心跳，不能單獨讓對局永久繼續。最後一位真人參與者及觀戰者都不在時，沿用共用的自動中止流程。
- 關閉網頁而未按「離開房間」，仍會在伺服器確認全員離線、最後連線的 60 秒重連寬限過後自動中止。伺服器每 5 秒檢查一次；網路中斷或裝置睡眠還可能需要額外時間才能偵測斷線，不能從關頁當下精準計時 60 秒。
- 任一真人仍開著有效遊戲分頁或觀戰頁，就可能保持房間活躍。關掉其中一個分頁，不會覆蓋同一人另一分頁的連線；公開復盤分享的訪客不算房間在線成員。
- 明確按「離開房間」會撤銷該身分。若已無任何登記真人或觀戰者，進行中的對局立即中止；只剩虛擬玩家也適用。
- 伺服器重啟時，所有保存中的對局都會獲得新的 60 秒重連寬限。服務停止時不會執行巡檢。
- 未完成局因全員離線中止，歷史原因記為 `empty`，不記勝敗；若在離線寬限內已正常完成，沿用正常完成結果。測試房仍不計入全站成績。

## 在 Pi 讀取目前房間清單

更新到包含本工具的版本後執行：

```bash
cd /opt/boardgame
sudo -u boardgame /opt/node24/bin/node scripts/inspect-rooms.mjs --data-dir /var/lib/boardgame
```

這是部署範本的帳號與資料位置。若你的服務使用其他帳號或 `DATA_DIR`，改用實際值；不需輸出整份私有環境設定。

只列出仍在進行，或資料無法判讀的房間：

```bash
sudo -u boardgame /opt/node24/bin/node scripts/inspect-rooms.mjs --data-dir /var/lib/boardgame --active-only
```

另可使用 `--room <房間ID>` 篩選一間房，或 `--json` 輸出結構化報告。

工具僅讀取房間索引及各房目前對局檔案，不啟動應用程式、不修改／刪除資料，也不列出暱稱、身分、牌面、憑證或邀請。它不用依賴 `.env`，不會連線到正式 API。

| 狀態／欄位 | 含義 |
| --- | --- |
| `active` | 保存的目前對局尚在進行，不等於此刻有人在線 |
| `lobby` | 已在等待室，沒有正在進行的對局 |
| `finished` | 已產生結果，可能正等待終局畫面展示完畢及回房巡檢 |
| `unreadable` | 對局缺檔、權限不足或格式異常；不能據此認定已結束 |
| 登記真人／虛擬玩家／登記觀戰 | 尚保有入房身分的數量；關頁後身分會保留，所以不是線上人數 |
| 上次結束 `empty` | 全員離線／離開而中止 |
| 上次結束 `host-ended` | 房主提前結束，未計勝敗 |
| 上次結束 `completed` | 正常完成，包括房主保留無盡挑戰成績後結算 |

資料檔以原子取代方式寫入。工具在讀取前後比對房間索引，若遇回等待室或換遊戲會重讀，最多三次；持續變動會明確提示稍後重查。清單仍是各房讀取當下的快照，並非跨房間的同一時刻，也無法取得只存在伺服器記憶體的即時連線。

結束碼 `0` 表示讀取完成且房間索引穩定，`1` 表示有無法判讀的房間或索引持續變動，`2` 表示參數／索引讀取失敗。使用 `--active-only` 時，摘要仍統計篩選範圍內所有房間，便於辨別「全部已回等待室」與「找不到資料」。

## 對局似乎沒有自動結束

先確認所有真人的遊戲與觀戰分頁均已關閉，再等候斷線偵測、60 秒寬限及巡檢。重跑上面的 `--active-only`；若仍有房間，不要直接刪 JSON。先確認服務是否運作，以及是否有生命週期巡檢錯誤：

```bash
sudo systemctl status boardgame --no-pager
sudo journalctl -u boardgame --since '10 minutes ago' --no-pager
```

`Room lifecycle reconciliation failed` 表示巡檢失敗，需要進一步檢查；`unreadable` 則先排查檔案權限、資料目錄與讀取錯誤。房間的正常終止入口是房主的「提前結束本局」，無盡挑戰若要保留成績則使用「以目前成績結束」，不要透過刪檔代替。
