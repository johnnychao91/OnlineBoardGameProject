# 測試分工與精簡原則

星匠工坊核對 90 張工藝卡與 10 位守護者的完整數值，測試任意合法星砂支付、資源上限的待處理選擇、保留牌可見性、守護者多選、十五分後同輪結束及作品數平手判定。整合測試以真實 Socket 在待處理階段重啟；完整 2／3／4 人局與測試房的統計邊界分別驗證。無合法行動的案例須由合法操作重現，過回合不能成為任意跳過回合的入口。

潛入防火牆規則層驗證 118 張牌、42 種路線拓撲、橋與雙彎分離、雙色門、跳躍節點、工具狀態、換手牌及三輪分紅。整合層獨立核對未知核心不洩漏、私下查看與交換後的重啟，以及正式／測試房的競賽統計；2～12 人均以合法虛擬玩家操作跑完三輪。

謝幕劫案規則層驗證精確牌庫、分贓餘數、單獨撤退、同類危機移除與珍藏跨幕保留。整合層驗證同版本並行秘密提交、私人金庫、重啟與五幕競賽結果；介面層驗證唯讀投影、公開戰報與操作條件。所有支援人數納入虛擬玩家完整五幕測試。

以保留可驗證的情境與斷言為優先，不以減少測試數量為目標。同一功能經過規則、伺服器、瀏覽器與公開分享等不同入口時，每一層都可能出現自己的錯誤，不能互相取代。

## 測試分工

廣告資格由 `server/advertising.test.ts` 驗證免密碼建房、暗語分類、舊房間、缺少設定與暗語衝突、環境設定升級優先序；`server/advertising.integration.test.ts` 遍歷全部遊戲，核對一般、免廣告與測試房，再以真實 HTTP 驗證玩家／觀戰一致、重啟、回等待室及換遊戲。`client/advertising.test.ts` 驗證授權前不輸出 SDK、手動載入去重、阻擋與逾時、房間上下文及已載入廣告後完整導覽。實際瀏覽器須檢查一般／免廣告／測試房、首頁、規則與隱私權頁，桌機／手機原有寬度與比例、下方間距及捲動；QA 攔截或本機替代 SDK，不使用真實帳戶產生廣告曝光。公開檢查器拒絕實際 publisher ID，環境範本不放入帳戶或暗語。

測試檔依序執行，避免多個整合測試伺服器爭用磁碟；同一案例中的多人／多房並行操作仍維持並行。真實連線與寫入可以等待完成，但遊戲內的 3 秒門檻、原始截止時間、改票取消、斷線寬限與輪末停留仍須檢查各自邊界，不能為了速度縮短遊戲時間或跳過斷言。

圖靈整合測試送出操作後，以同一 Socket 的授權同步等待房間佇列完成，連線與 I/O 等待上限為 10 秒。同步後要求儲存版本恰好增加一次，並獨立核對每位玩家的 `update` 廣播；不能用同步回覆取代廣播驗證，也不能只收到廣播就視為寫入完成。慢寫入回歸延遲 4.25 秒，確認先收到廣播時仍在等待持久化；過期操作則必須明確失敗。正式服務的時間與規則不因此調整。

## 何時可以合併

- 同一層、同一前置狀態、同一操作路徑與觀察時點才是候選。不同人數、種子、角色、模式、版本、觀看者或重啟前後時點不直接視為重複。
- 刪除案例前，逐條指出其斷言由哪個保留案例負責；獨有斷言必須搬移。同輸入的純渲染或固定回應可保存結果，供多個斷言使用。
- 驗證重試、冪等、快取、多分頁或副作用的重複呼叫本身就是測試內容，不能快取掉。不同案例仍應各自建立乾淨資料，避免依賴執行順序。
- 保留失敗定位清楚的案例。不要為省一次準備就把不同持久化邊界合成一個大流程，也不要把真實 HTTP／Socket.IO 測試全部換成 mock。

## 精簡與補測的覆蓋對應

音效游標只測現行 `GameSoundTracker`；已移除未被介面使用的 `StationSoundTracker` 與六項舊案例。原有掛載／重掛載、換房、換視角、不同行動者、重複／過期紀錄、漏幀多事件及斷線／停用／缺少快照的邊界，集中由 `sound-cues.test.ts` 驗證，太空維修站事件另經目前 registry 的 soundAdapter 接入。`station-sounds.test.ts` 保留音訊輸出、音量、靜音與資源清理。

共用 `SpectatorRoster` 不依遊戲或階段分支，因此 `host-identity.test.ts` 的六種授權渲染矩陣只執行一次，從 198 次減至 6 次；每款遊戲的伺服器移出授權仍由 `role-switch.test.ts` 保留。前端 registry 契約移除 SSR 不含 `MAKE_MOVE` 的斷言：SSR 不會序列化事件 handler，該字串不能證明唯讀。登錄、投影渲染、章節與公開音效契約繼續測試；實際唯讀操作仍需伺服器及瀏覽器驗證。

| 原本重複工作 | 保留的驗證 |
| --- | --- |
| `features.test.ts` 額外建立一次 8 人房，觀戰、開局後拒絕再加入 | 既有 4～8 人參數化案例包含同一 8 人流程；觀戰者的 `access`、人數及沒有 `playerID` 的斷言移入每種人數。開局狀態、憑證與 HTTP 409 斷言保留 |
| `api.test.ts` 對固定 401 回應呼叫相同 API 兩次 | 同一 rejected promise 同時檢查錯誤名稱、狀態及 `ApiError` 型別 |
| `station-display.test.ts`、`host-identity.test.ts`、`test-room.test.ts` 對相同輸入重複 SSR | 每種輸入渲染一次，仍檢查不讀秘密、內容、禁用狀態與容量 |
| 圖靈舊桌面測試標為 v4 卻建立目前新版 | 明確建立 v3／v4／v5，各自保留缺失、空白、部分排列及重啟／換輪情境，並驗證實際版本 |
| 非法暱稱案例被 `numPlayers` 先攔截 | 分開送出人數與名稱錯誤，均檢查 HTTP 狀態及對應原因 |
| `TuringApproval`、`MoonSnapshot`、`TuringSnapshot` 相同輸入重複 SSR | 每個相同狀態及視角共用一次 HTML，減少 7 次渲染，全部斷言保留 |
| 圖靈測試在同一狀態重讀統計、重複拒絕不存在席位及新版停用操作 | 共用一次統計回應；保留未知席位拒絕、獨立 no-op 放牌驗證、v2／v3 牌主授權與 v4／v5 禁用操作；真正的重試／冪等測試不動 |
| 虛擬玩家不同模式顯示相同測試名稱 | 名稱加入排序及挑戰模式，各人數、玩法、種子與合法動作覆蓋保留 |

同時將公開規則預覽的固定兩款遊戲清單改為 `GAME_IDS`，所有登錄遊戲都檢查 GET、HEAD、尾斜線、拒絕額外路徑／POST，以及不洩漏私人輸入、不改動房間。新增遊戲會自動加入這組檢查。

## 驗證方式

在專案目錄使用 Node.js 24：

```sh
npm test
npm run test:public
npm run check:public
npm run build
```

`npm run build` 包含完整型別檢查，完整驗證流程不另重跑一次；需要單獨快速確認時仍可使用 `npm run typecheck`。GitHub Actions 在 Windows 與 Ubuntu 執行相同流程。Windows 專屬路徑大小寫測試在其他平台略過，不應改成所有平台略過。

精簡前後應比對測試名稱及斷言對應，再執行完整測試。測試總數或單次耗時不能代表覆蓋完整度；時間會受磁碟與系統負載影響。若要保存 JSON 測試報告，輸出到 Git 外的私人工作目錄。

SSR 測試驗證產生的標記與資訊邊界；它不驗證真正瀏覽器的像素排版或點擊流程。修改介面時仍須依[遊戲框架驗收](GAME_FRAMEWORK.md)檢查桌機、手機、觀戰與回放。

百鬼夜宴需驗證全部 16 種能力、官方 A／B 場景與自訂中央牌、先能力後罰款、共同勝利及換座後續手。真假交換需比對各玩家與盲視角投影，百目鬼私看與青行燈排除目標的情報不能經由公開紀事、音效或 PNG 外洩。瀏覽器包含 4／12 人、6／8 人特殊能力、美術風格與手機；必須操作查看、宣告、逐人認領、能力選擇、自訂設定保存、隱私收合與復盤切換。

貝克街迷霧的瀏覽器檢查需包含四年代、4／6／12 人及美術風格；分別操作執行者選牌、福爾摩斯六板提示與換板、發言、錯誤破案扣警徽、正確破案及華生指認。另檢查手機證物放大、圖鑑搜尋分頁、年代背景、PNG 及盲／上帝復盤切換。完整牌庫的圖鍵必須對應實際圖片，不能以尚未載入的空圖通過最終美術驗收。

房主移出觀戰者由 `role-switch.test.ts` 覆蓋全部遊戲、參與／觀戰房主、跨房與非房主拒絕、身分切換競態、儲存失敗、重啟後撤銷及多分頁在線期限；`host-identity.test.ts` 檢查等待室、對局與結束畫面的按鈕權限。瀏覽器另驗證確認／取消、被移出者所有分頁退出、有效邀請重新加入，以及美術風格在桌機與手機的名單排版。

圖靈測試需額外檢查 2～10 人群體校準每人一張、任意玩家移動任意卡、滑鼠與觸控拖放、點卡再點位置、改序清除同意，以及無盡模式生命耗盡後的成績與戰報。檢測員玩法保留 4～9 人逐張揭牌，10 人選檢測員須明確拒絕開局，不可丟棄玩家或偷偷改玩法；改群體校準後可由同一批 10 人開局。

排序、重抽及下一輪的房主／全員／任一玩家同意須各自驗證；房主模式另檢查觀戰房主不可投票、交接、重啟及排隊期間身分失效，普通觀戰與回放仍唯讀。無盡「以目前成績結束」位於房間管理，玩家與觀戰房主皆可操作；測試房也有此入口並保留結果及回放，但生命耗盡或房主結算都不計全站成績。舊局缺少同意設定時維持全員同意，文字、雙卡、語音確認及 v4 舊存檔均保留相容測試。新局沒有文字輸入框，也不要求麥克風權限；實際外部通話由玩家使用自己的語音軟體，瀏覽器測試只驗證網站操作與權限邊界，不代表測試了第三方通話服務。

潛入防火牆的多人批次確認使用真實 Socket 同版本提交，先等待全部操作的預期版本持久化，再做一次已授權的完整同步，最後逐一核對所有參與連線的廣播版本。不要為同一批次對每人重複完整同步：每次會重讀整局存檔並保存連線中繼資料，12 人時容易在慢速磁碟造成同步逾時。回歸測試只延遲完整同步讀取一秒，保留原本十秒同步上限，確認單次同步及各人私人投影；既有三輪、重啟、觀戰、分享與統計案例全部保留。
