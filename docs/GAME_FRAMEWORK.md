等待室選定遊戲後，在開始操作區下方顯示該遊戲的全站統計。所有已登錄遊戲共用首頁統計元件與公開資料來源，包含各自勝敗、挑戰及個人競賽排行；切換遊戲後只顯示新的選擇，尚未選擇時不顯示，首頁維持完整遊戲清單。

所有遊戲實戰與觀戰的名稱顯示於網站標誌旁，音效及音量透過共用 Header 插槽移到頂端；各遊戲沿用同一個聲音狀態與偏好，不另外建立播放來源。歷史復盤覆寫為該局的遊戲名稱與規則連結，關閉後恢復目前房間；復盤仍不播放即時提示音。桌機與手機皆適用，首頁及規則頁維持原本標題。

# 遊戲框架

謝幕劫案的危機門檻由房主在開局前選擇同類第 2 張或第 3 張，預設及舊存檔採第 2 張。設定沿用共用的驗證、準備清除、房間持久化與瀏覽器記憶；開局後固定。門檻屬公開資訊，實戰、觀戰、復盤及 PNG 一致顯示，第三張的個人競賽統計另分組。

遊戲選單、規則導覽與總覽、全站統計沿用 `src/games/catalog.ts` 的共用顯示順序：太空維修站、加密通話、黑霧襲城、銀月列車、圖靈測試、午夜郵局、貝克街迷霧、百鬼夜宴、謝幕劫案、潛入防火牆、星匠工坊。伺服器註冊表依此排序，不使用模組加入順序作為顯示順序；房間內各局歷史仍依實際對局時間排列。

星匠工坊以 `star-workshop` 登錄 2～4 人個人競賽。資源與已購作品公開，盲抽保留只公開不含牌面資訊的識別碼與等級；本人及授權上帝視角才可查閱內容。退還資源與選擇守護者皆是持久化的本人待處理操作，完成後才推進回合與十五分判定。公開 PNG 再次依公開欄位取值；競賽統計依人數與完整桌輪聚合。詳見[星匠工坊](STAR_WORKSHOP.md)。

潛入防火牆以 `firewall-breach` 登錄 2～12 人三輪個人競賽，採完整基本加擴充規則。網格、公開狀態與個人手牌分別投影，未知核心的合法放位不依祕密路線裁定；上帝視角也不取得未來牌堆或未翻目標配置。每回合依共同版本裁定，輪初與輪末確認採階段版本，可接受多人同版本確認。統計以三輪競賽聚合，測試房排除；詳見[潛入防火牆](FIREWALL_BREACH.md)。

謝幕劫案以 `curtain-heist` 登錄 3～8 人五幕個人競賽。玩家的私人金庫與未揭曉決策分開投影；每批決策使用共同階段版本，並行提交不因同伴先送出而失效。公開動作中繼資料隱藏，全部選擇收齊才結算撤退及下一張牌。統計採五幕競賽聚合，測試房不計成績。詳見[謝幕劫案](CURTAIN_HEIST.md)。

百鬼夜宴以 `hundred-ghosts` 登錄，支援 4～12 人。真實面具只在伺服器保存，玩家取得歷史觀察記憶；查看本人的目前面具必須花費回合。真假盲換的公開動作、投影與音效一致。絡新婦改變遊戲內座次，不改房間認證席位；青行燈的特殊揭示不能送給面具持有者。統計採個人競賽，介面的玩法名稱與輪次單位由各遊戲登錄定義。詳見 [百鬼夜宴](HUNDRED_GHOSTS.md)。

在本專案的需求與對話中，「遊戲框架」指跨遊戲的共用功能。要求框架新增功能，代表所有現有遊戲都適用；新增遊戲也必須接上當時已具備的全部框架。各遊戲透過適配器決定呈現內容，授權與房間流程保持共用。

## 前兩款遊戲的盤點

廣告資格是共用房間屬性：建房時由伺服器依一般／免廣告／測試密碼保存，不由玩家設定或遊戲狀態決定；所有已登錄遊戲與觀戰皆沿用。首頁不載入，房間授權後才載入手動廣告；帶房間上下文的規則與隱私權頁重新驗證身分。免廣告房仍計正常成績，測試房仍排除。SDK 載入後離開頁面採完整文件導覽，避免免廣告頁沿用先前 SDK；SDK 錯誤不影響遊戲。帳戶碼、廣告單元與密碼留在私人環境設定，詳見 [廣告與隱私權](ADVERTISING.md)。

框架不代表每個遊戲都要有宣稱、剪線、數字牌或相同的勝利條件。這些屬於遊戲規則。跨遊戲的是資訊權限、操作提示、共用控制及承載它們的流程。

觀戰名單共用房主移出操作，等待室、對局中與結束畫面皆可使用；觀戰房主不能移出自己。伺服器在房間佇列內重新確認房主及觀戰身分，保存撤銷後清除該身分所有分頁的在線期限。舊憑證及原加入重試不再有效，重啟也不能恢復；有效邀請可發起新的加入。此操作不更動參與者、準備狀態、牌局或成績。

已登錄的雙陣營對抗遊戲共用勝敗交鋒圖，依 `factionLabels` 順序由左至右呈現，交界使用實際勝場比例；雙方都有勝場時加入美術碰撞特效。平局不計入比例，沒有勝敗時顯示中性狀態；合作遊戲仍呈現全隊成敗，其他陣營數保留一般統計。特效尊重減少動態效果偏好，不變更統計資料或遊戲規則。

挑戰型結局可由 `GameOutcome.challenge` 提供模式、完整通過關數與起始生命。完成局總數仍包含挑戰，但一般勝率使用 `rankedCompleted`；挑戰依模式、人數與起始生命分組，顯示次數、最佳與平均通過關數。歷史與戰報沿用同一結果；無盡挑戰可在生命耗盡或房主選擇保留目前成績時結束，不計入普通勝敗。測試房及不計成績的中止局仍不列入成績；謝幕劫案單局收益排行可顯示當局暱稱，不跨局合併身分。

每款遊戲的詳細規則必須提供公開圖鑑，使用共用 `RoleGallery` 呈現角色、設備或道具，透過前端必填的 `gallery: { chapter, label }` 指向已登錄章節，規則總覽便會提供對應的直達連結。太空維修站收錄兩種身分與三種設備，加密通話收錄訊號牌、掩護與靜默脈衝，黑霧襲城與銀月列車各收錄十種角色，圖靈測試收錄檢測終端、強度晶片與人性容錯核心。角色顯示陣營，設備與道具顯示分類，不將設備誤認為玩家陣營。

圖鑑只使用靜態公開介紹與本機素材，所有玩家皆可查看；不讀取房間、玩家身分或秘密狀態。加密通話的數字是固定教學範例，不是任何玩家的手牌。新增遊戲須提供適合該遊戲的圖鑑內容、入口與章節，不須在規則總覽加入遊戲名稱判斷。既有圖鑑片段網址保持可用。

## 黑霧襲城如何接入

黑霧襲城沿用上表全部共用功能，另提供 5～10 人組隊表決、秘密任務、角色開局情報、深海之刃指認與兩種詛咒之鐘模式。房主在等待室選擇角色與鐘聲模式；設定更新會產生新的等待對局 ID 並清除準備，避免舊畫面的確認套用到新設定。開局時依真實人數驗證角色席位，不會暗中丟棄選中的角色。

任務結果停留至所有玩家確認，顯示誰尚未確認。即時提示音只根據已公開結果與自己的行動提示，不會透過聲音透露其他人的秘密選擇。上帝視角可以查看當下私人資訊；任何視角都無法預知隨機模式尚未抽出的鐘牌。盲視角始終只看到任務票數，不包含個別出牌者。

黑霧襲城與銀月列車的名冊陣營標示，與右側私人資訊共用顯示狀態；收起、遮住或切換分頁時，同步清除名冊上的陣營顏色與私人標籤。回到分頁後須手動展開。標示只讀當前視角已授權的資訊，不能將未知玩家推測為另一陣營；上帝視角切回盲視角仍須重新投影資料。

## 新遊戲必須實作的介面

貝克街迷霧以 `baker-street` 登錄 4～12 人、四年代案件。年代、年份、牌數、身分配置、特別圖板及指定福爾摩斯沿用公開房規保存；真正開局驗證指定席位與人數。卡片和圖板保存完整內容快照；觀戰、復盤與圖鑑皆沿用授權投影。三輪鑑證與破案由伺服器裁定，秘密選牌和華生情報不由公開協定洩漏。雙陣營結果沿用統計交鋒圖，測試房排除統計；詳見[貝克街迷霧](BAKER_STREET.md)。

午夜郵局以單一 `midnight-post` 登錄三種玩法：3～4 人密函投遞、5～8 人全城夜遞及 2～6 人黑函局長。前兩者是個人競賽，以 `GameOutcome.competition` 保存玩法及夜數並另列聚合，不以座位或暱稱當作陣營；局長玩法使用固定雙陣營。開局驗證可接收真實參與者 ID，確保指定的公開身分仍在參與名單。待處理效果與私人選項皆由同一引擎管理，所有視角剝除未來牌堆；細節與來源見[午夜郵局](MIDNIGHT_POST.md)。

圖靈測試沿用全套框架，以房規選擇題庫、標準五關或無盡模式及起始生命。新版「群體校準」支援 2～10 人每人一張、全員共用排序桌；4～9 人也可選檢測員玩法，除檢測員外各一張。2～3 人固定採群體校準，既有多人檢測員局不改規則。共排桌允許所有參與者搬動任何人的牌，排列變更即更新版本、清空同意，達成房規的同意條件才原子揭牌與結算。撤回同意更新版本並保留他人的票，防止已撤回的舊操作延遲生效。伺服器保存桌面排列及同意，拒絕過期操作；公開資料不含未揭強度，私人面板收起也遮住自己桌上的數字。觀戰、復盤及 PNG 沿用公開桌面，Snapshot 保持唯讀，PNG 不讀私人牌面。

新局透過外部語音作答，直接進入排序，不需開場或口述完成確認；網站只保存題文、排列、同意與揭牌結果，不存取麥克風、不錄音、不保存逐字稿。每張卡的操作與揭牌皆驗證席位、階段與版本；只投影本人或獲准上帝視角的強度。新共排桌的無盡結果使用 `endless-table`，與既有 `endless` 檢測員成績分組。已保存的 v1 文字、v2 雙卡、v3 語音確認及 v4 依人數選玩法的流程維持相容；新局為 v5，保存排序玩法。

圖靈測試共排桌所有卡牌直接列在桌上，舊局未列入的牌會接續補齊，可以直接同意初始順序。準備狀態放在姓名旁，排序同意與下一輪確認共用右側操作區；秘密資訊只由手動開合，切換視窗或分頁不會改變。v4 可在尚未揭牌時依房規同意方式重抽，保留數字、關數與生命，將全牌重設為初始順序並清除先前排序同意；提案尚在時不揭牌，重抽與揭牌沿用同一房間佇列及版本驗證。題目讚／倒讚則是獨立的題目回饋，不改變遊戲狀態與勝敗；只接受當局參與者對目前題目快照的投票，同一局、席位、題目內容不重複計票。正式內建題按內容版本聚合，測試及自訂題隔離；持久化資料留在 Git 外。

重抽、共排桌確認與下一輪確認各自保存 `host`／`all`／`any` 同意方式，預設及缺省舊存檔採 `all`。`any` 僅限參與玩家，任一人按下即執行；`host` 僅限仍在當局參與名單中的現任房主，一人按下即執行，不需其他人先提案。房主在觀戰時禁選 `host`，舊設定或身分變動造成房主無法參與時退回 `all`。三項選單即時儲存；遊戲中的設定入口放在左上方「房間管理」，等待室仍在遊戲設定區。遊戲中變更清除舊同意並更新版本；標記隨當前階段策略顯示。房主專用引擎操作不登錄於公開 Socket 協定；在房間佇列重驗權限、對局與版本，沿正常引擎更新隨機狀態、紀錄與持久化。觀戰房主可修改 `all`／`any` 規則及在「房間管理」結算無盡挑戰，不能冒用參與玩家投票；普通觀戰、復盤及分享不能取得操作路徑。

題目回饋的新版協定分成 `topic`、`low`、`high` 三個獨立評分項目，各自去重與撤回。舊整題評分留在原欄位，不能當成主題票；題目快照內容更新後重新累計。等待室設定記憶是共用框架：房間按遊戲保存已套用設定，回房與中途離場不清空。瀏覽器只記錄目前房主收到的公開設定，不寫入憑證或對局秘密；新房初次選遊戲才提供偏好，既有房間的設定永遠優先。舊房間以目前 `gameOptions` 初始化，不需資料遷移。

自訂內容是房間公開設定，不自動加入全站題庫；只有已認證房主的遊戲選擇與選項路由可接收較大的題庫請求，其餘請求仍維持原上限。每關抽中時保存完整題文，因此已完成關卡的歷史不依賴更新後題庫；無盡模式以精簡 ID 記錄本輪題池已抽題目，抽完再循環且不連續同題。所有視角均剝除伺服器抽題記錄與舊版未來題目佇列。舊版文字局依保存的規則版本繼續原流程，封存回答只對本人及獲准上帝視角公開，直到全員提交才公開文字。

銀月列車也沿用上述框架，線上與現場輔助是同一款遊戲的房規模式。現場模式仍有私人裝置身分、邀請與憑證、觀戰、復盤、分享與統計；不另外建立沒有授權的裁判入口。警長開關與各項倒數由房主在等待室設定，修改後全員重新準備。

框架新增伺服器倒數適配器 `advanceClock(state, now)`：由每房共用佇列依持久化截止時間推進，和玩家操作、房主中止及回房流程序列化。重啟後沿用原截止時間，每次最多推進一個階段，下一階段給完整時間。沒有此適配器的遊戲照原流程運作。玩家送來的時間不能改動裁定；瀏覽器只用伺服器時間樣本顯示倒數，回放不跑即時倒數。

銀月列車的夜晚顯示目前職業與實際段數。新局依開局公開配置略過未登場職業；已登場後離場者仍保留時段。守衛、預言家、女巫無論是否完成操作，皆等待完整公開倒數，避免以時段長度推測存活；進行中的舊局也忽略神職已保存的提前期限。只有存活狼人一致選擇襲擊目標後，伺服器可在 3 秒後提前切換；一致被打破則取消提前期限。狼人私人期限僅存於伺服器，玩家、盲／上帝觀戰與回放投影都不含該欄位，畫面持續使用原公開期限。掩護點擊只存在本機，不寫入遊戲、歷史或統計；夜晚不公開個人的送出狀態，不播放角色專屬聲音。即時上帝觀戰沿用既有授權。

1. `src/games/catalog.ts`：公共名稱、說明、人數與規則介紹。等待室容量、目錄及規則路由由此延伸，不需要改固定人數或路由清單。
2. `src/games/<game>/game.ts`：boardgame.io 規則、唯讀投影、原創敘述、伺服器動作驗證。玩家 ID 必須接受框架的實際席位，不假設連續或從 0 起算。
3. `src/games/registry.ts`：開局設定、可入座狀態、觀戰投影、結果、選填的公開房規正規化與驗證、選填的終局展示時間與伺服器倒數適配器。
4. `src/client/game-registry.tsx`：`PlayerClient`、`Snapshot`、`DetailedRules`、章節、圖鑑 `gallery`、`createPoster`、`soundAdapter`、結果文字；有房規時再加 `LobbyOptions`。缺少必填功能會使型別檢查失敗。
5. 實戰透過 `RoomContext` 取得共用房間狀態，顯示 `GameSoundControl`；觀戰、復盤、戰報、詳細規則及房規入口均由框架載入已登錄適配器。
6. 提供美術畫面，保留原創素材與生成提示；只依已授權資料選圖。PNG 產生器必須再次只讀公開欄位，不能直接輸出上帝視角物件。

`gameCatalog` 是目錄唯一來源；伺服器／前端註冊仍需實作遊戲特有的規則與畫面，框架無法憑名稱生成這些內容。新的共用功能應加在中央介面與共用流程，並補上所有適配器，避免之後只替某款遊戲接線。

測試房間的 `testRoom` 是伺服器在建立時認證並固定的房間屬性，客戶端不能用布林參數將一般房間改為測試房間。全站統計略過該房的所有歷史與當前對局。虛擬玩家使用內部憑證、與真人一樣占席位，只能由房主在等待室新增或移除；不授予額外視角、不接任房主、不建立在線租約。真人全部離開仍沿用自動中止規則。

新增遊戲須同時在 `src/games/bots.ts` 提供合法隨機動作適配器，登錄測試會檢查所有遊戲都有支援。決策先經正式 `playerView`，只能使用公開資訊與該席位獲准取得的私人資料。執行器每房每次最多一個動作，和真人操作、中止、換局、倒數共用佇列，透過 boardgame.io `Master` 正常裁定與保存，禁止直接改角色或勝負。操作只為測試介面，不是策略型對手。

## 驗收

銀月列車配置沿用同一遊戲 ID。等待室透過 `validateLobbyOptions` 驗證選項，允許玩家尚未到齊時先選固定人數配置；真正開局仍由 `validateOptions` 依實際參與人數檢查。新局保存完整公開配置與規則版本，舊局／回放不重新套用最新配置表。平局以獨立 `draws` 欄位統計，不算入任一陣營勝場；其他遊戲沒有平局時為零。

特殊角色的死亡、反傷與連鎖開槍由伺服器結算；隱藏死因及待執行佇列不投影到客戶端。明牌僅在出局後公開，白癡翻牌則公開角色與失票狀態。公開角色不能因收起私人資訊而消失。新角色的合法動作須同步涵蓋虛擬玩家、觀戰／回放、提示音與公開戰報。

各測試層的責任與重複案例合併原則見[測試分工](TESTING.md)。精簡時保留所有遊戲、人數、視角、模式與持久化邊界，不能只挑一款遊戲代表整個框架。

- `framework.test.ts` 依目錄逐款驗證入座、房主觀戰、觀戰權限、中止回房、邀請與重啟保存；擴充目錄即納入測試。
- 註冊契約測試檢查目錄、伺服器與前端一致，所有遊戲有規則、圖鑑入口、戰報、唯讀畫面及提示音適配器，並確認圖鑑指向有效規則章節。
- 各規則測試覆蓋勝敗、非法操作、重複／過期動作、秘密資訊；整合測試驗證實際 Socket.IO、統計、回放分享與多房隔離。
- 桌機與手機實際瀏覽器檢查實戰、觀戰、回放；美術風格與既有音量偏好、房主操作、PNG 和詳細規則都要可用。
- 更新保持既有遊戲 ID、歷史、偏好儲存鍵與憑證相容；實際部署資料一律留在 Git 外。
