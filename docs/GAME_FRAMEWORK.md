# 遊戲框架

在本專案的需求與對話中，「遊戲框架」指跨遊戲的共用功能。要求框架新增功能，代表所有現有遊戲都適用；新增遊戲也必須接上當時已具備的全部框架。各遊戲透過適配器決定呈現內容，授權與房間流程保持共用。

## 前兩款遊戲的盤點

| 功能 | 框架提供 | 太空維修站的內容 | 加密通話的內容 |
| --- | --- | --- | --- |
| 建房與遊戲切換 | 可先建房再選遊戲；等待室換遊戲保留成員、邀請與歷史，清除準備 | 4～8 人 | 2～4 人 |
| 人數與席位 | 依實際入座人數開局；容量取登錄遊戲的最大值，目前 10 席 | 依人數配置角色與設備 | 依人數配置掩護與目標頻段 |
| 邀請與身分 | 有時效的 fragment 邀請、獨立憑證、同瀏覽器重連、重試去重 | 共用 | 共用 |
| 玩家與觀戰席 | 名單分開、觀戰不占人數、等待室可切換 | 共用 | 共用 |
| 房主權限 | 玩家改觀戰仍是房主；可開局、移出待開始玩家、更新邀請、中止對局 | 共用 | 共用 |
| 房間生命週期 | 結束回原等待室、每局獨立 ID、全員離線 60 秒後中止、歷史保存 | 終局桌面保留至少 8 秒 | 頻段與全隊結果 |
| 準備與階段確認 | 入座準備、避免舊分頁操作、顯示尚未完成確認的人 | 開局情報、輪末準備、宣稱 | 頻段同步、暫停、脈衝決議 |
| 伺服器裁定 | 每房獨立佇列、憑證與來源驗證、隔離持久化、隱藏資料投影 | 陣營、設備順序、公開預選與檢修 | 數字手牌、伺服器收到的傳送順序 |
| 觀戰 | 即時盲視角／上帝視角、唯讀、每遊戲投影 | 身分及設備 | 訊號手牌 |
| 復盤 | 完成局時間軸、前後步驟、自動播放、視角切換、歷史遊戲身分固定 | 逐次檢修 | 逐次傳送、破綻與脈衝 |
| 分享 | 7 天唯讀復盤連結、伺服器鎖定視角、房主撤銷；公開 PNG 戰報 | 檢修事件圖 | 訊號事件圖 |
| 統計 | 全站、遊戲、陣營／合作結果、人數；只計完成局、不以暱稱追蹤個人 | 維修員／干擾者 | 全隊成功／失敗 |
| 版面 | 桌機視窗內排版、歷史在左、私人區在右；觀戰／復盤對應實戰；手機自然捲動 | 設備桌面與身分側欄 | 訊號牌與頻段狀態 |
| 詳細規則 | 統一目錄、獨立網址、新分頁入口、房間共通規則 | 模組、宣稱、檢修 | 沉默、傳送、掩護、脈衝 |
| 精簡／美術 | 新玩家預設精簡，記住選擇；按權限載入原創圖、不改規則狀態 | 場景、設備、身分圖 | 場景、數字牌框、道具圖 |
| 提示音與音量 | 共用 0～100%、預設 50%、靜音、偏好記憶、手勢啟用、重連不補播；復盤不播即時音效 | 翻開設備、輪到自己 | 頻段完成、需要重新同步；沒有節拍或逐張傳送音 |
| 品牌與分享預覽 | 統一網站名稱與本機圖示，公開預覽不含房間秘密 | 共用 | 共用 |
| 部署與更新 | Windows／Linux、單一服務、多遊戲資料、備份、公開內容檢查 | 共用 | 共用 |

框架不代表每個遊戲都要有宣稱、剪線、數字牌或相同的勝利條件。這些屬於遊戲規則。跨遊戲的是資訊權限、操作提示、共用控制及承載它們的流程。

## 黑霧襲城如何接入

黑霧襲城沿用上表全部共用功能，另提供 5～10 人組隊表決、秘密任務、角色開局情報、刺客指認與兩種詛咒之鐘模式。房主在等待室選擇角色與鐘聲模式；設定更新會產生新的等待對局 ID 並清除準備，避免舊畫面的確認套用到新設定。開局時依真實人數驗證角色席位，不會暗中丟棄選中的角色。

任務結果停留至所有玩家確認，顯示誰尚未確認。即時提示音只根據已公開結果與自己的行動提示，不會透過聲音透露其他人的秘密選擇。上帝視角可以查看當下私人資訊；任何視角都無法預知隨機模式尚未抽出的鐘牌。盲視角始終只看到任務票數，不包含個別出牌者。

## 新遊戲必須實作的介面

1. `src/games/catalog.ts`：公共名稱、說明、人數與規則介紹。等待室容量、目錄及規則路由由此延伸，不需要改固定人數或路由清單。
2. `src/games/<game>/game.ts`：boardgame.io 規則、唯讀投影、原創敘述、伺服器動作驗證。玩家 ID 必須接受框架的實際席位，不假設連續或從 0 起算。
3. `src/games/registry.ts`：開局設定、可入座狀態、觀戰投影、結果、選填的公開房規正規化與驗證、選填的終局展示時間。
4. `src/client/game-registry.tsx`：`PlayerClient`、`Snapshot`、`DetailedRules`、章節、`createPoster`、`soundAdapter`、結果文字；有房規時再加 `LobbyOptions`。缺少必填功能會使型別檢查失敗。
5. 實戰透過 `RoomContext` 取得共用房間狀態，顯示 `GameSoundControl`；觀戰、復盤、戰報、詳細規則及房規入口均由框架載入已登錄適配器。
6. 提供精簡與美術畫面，保留原創素材與生成提示；只依已授權資料選圖。PNG 產生器必須再次只讀公開欄位，不能直接輸出上帝視角物件。

`gameCatalog` 是目錄唯一來源；伺服器／前端註冊仍需實作遊戲特有的規則與畫面，框架無法憑名稱生成這些內容。新的共用功能應加在中央介面與共用流程，並補上所有適配器，避免之後只替某款遊戲接線。

## 驗收

- `framework.test.ts` 依目錄逐款驗證入座、房主觀戰、觀戰權限、中止回房、邀請與重啟保存；擴充目錄即納入測試。
- 註冊契約測試檢查目錄、伺服器與前端一致，所有遊戲有規則、戰報、唯讀畫面及提示音適配器。
- 各規則測試覆蓋勝敗、非法操作、重複／過期動作、秘密資訊；整合測試驗證實際 Socket.IO、統計、回放分享與多房隔離。
- 桌機與手機實際瀏覽器檢查實戰、觀戰、回放；兩種視覺模式與舊偏好、房主操作、PNG 和詳細規則都要可用。
- 更新保持既有遊戲 ID、歷史、偏好儲存鍵與憑證相容；實際部署資料一律留在 Git 外。
