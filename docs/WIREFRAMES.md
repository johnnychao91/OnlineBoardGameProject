# 手機版介面規格

直接開啟 [mobile-wireframes.html](./mobile-wireframes.html) 可檢視六個主要畫面與首頁統計示意。它使用內嵌 CSS 與假資料，不需要啟動服務、不會對外請求素材，也不會產生可用的邀請或憑證。設計基準為 390 px；窄螢幕可橫向捲動比較。

正式介面位於 `src/client/`。手機使用單欄，桌面把房間分享或對局紀錄移到側欄，支援至少 320 px 寬度。主要操作至少 44 px 高；深靛藍作底、薄荷青表示維修與可操作區、琥珀表示危機與秘密視角。狀態都有文字，不能只依靠顏色辨識。

頁首另提供小型「精簡／美術」試用切換，預設精簡。美術模式加入陰暗手繪太空艙／諜報通訊室插畫、紙感面板及相配色調，沿用相同操作與桌面分欄；圖片只是裝飾，不代表秘密資訊。此瀏覽器會記住偏好並同步至同源分頁，儲存受限時仍可在當前分頁切換。首頁、等待、實戰、觀戰、回放與規則頁皆可切換；選擇另一遊戲及查看舊局時依當時遊戲套用主題。手機保留可捲動排版，精簡模式不下載這兩張美術背景圖。

## 1. 建立與加入

- 開房者只需填暱稱，**不預選遊戲或玩家人數**。先開房邀朋友集合，在等待室再由房主選擇遊戲。
- 開房密碼放在收合欄位，預設不儲存。可勾選「在這個瀏覽器記住」，成功開房後才儲存，下次自動帶入；可取消勾選或清除。共用裝置不建議記住。開房成功後，房主直接進等待室。
- 朋友開啟 `/join/{roomId}#invite={token}`，前端把 token 暫存目前分頁並立即從網址列移除，再選「參與遊戲」或「先來觀戰」並填暱稱。
- 玩家只在開局前加入；觀戰者不占座位、不計入開局人數，開局後仍可透過邀請加入。
- 同一瀏覽器同一房間只儲存一種身分。已加入時顯示「回到我的座位」或「回到觀戰席」，不重複加入；進入等待室後可切換身分，開局後固定到返回等待室。
- 玩家使用獨立座位憑證；觀戰者使用獨立觀戰憑證。兩種憑證都不會出現在邀請或公開復盤連結。
- 加入請求帶有暫存在當前分頁的 UUID；同邀請、同模式與 UUID 可安全重試，不會因回應遺失再占一席。成功後清掉邀請與 UUID；不同邀請重設 UUID，玩家／觀戰請求分開保存。

## 2. 等待與分享

- 等待室使用 HTTP 房間狀態，尚未掛載 boardgame.io 對局。參與名單只顯示已入座玩家，不預造固定人數的空位，觀戰名單另列。
- 房主（含觀戰房主）可在等待室即時選擇／更換遊戲，其他人同步看到目前遊戲與規則。未選定前不能準備或開局；換遊戲後全員重新準備，保留邀請、成員、房主與歷史。
- 房間參與席最多 8 位，開局另依遊戲範圍判定。選到上限較少的遊戲時不踢人，清楚提示超額人數及自行改為觀戰的方式；遊戲進行中不提供換遊戲。
- 顯示目前玩家人數、人數上下限、已準備數與觀戰席。觀戰席可收合，列出暱稱並在自己的名字旁標示「你」；空名單顯示邀請朋友觀戰的提示。觀戰人數是持有有效觀戰身分的人數，不宣稱全部在線。
- 「房間身分」區顯示目前身分及「改為觀戰」／「改為參加遊戲」。切換保留暱稱、邀請及歷史；改為玩家需準備，其他玩家的準備狀態保留。席位已滿時停用入座按鈕並說明等待空位。
- 房主改為觀戰時釋出玩家席位但保留管理權，觀戰名單標示「房主」。觀戰房主不需準備，可在參與者全部準備且人數足夠後開局；也可管理邀請、移出玩家及提前結束。沒有玩家時仍保留房主，其他人入座不會接管。對局中停用切換並說明返回等待室後可操作。
- 切換時顯示「正在切換…」；若網路遺失回應，保留原請求並顯示「重試身分切換」，重新整理後仍可恢復同一次結果。其他同源分頁跟隨儲存的最新身分，過期回應不覆寫新身分；這項跨分頁協調使用 Web Locks，需新版瀏覽器及 HTTPS／localhost。
- 玩家按準備；符合所選遊戲人數且全員準備後，房主按「以目前 N 位隊員開始」。伺服器在此時鎖定本局實際人數。觀戰者不需準備。
- 房主可在其他玩家旁按「移出」，確認視窗列出暱稱並說明可用有效邀請重新加入；房主不可移出自己，開局後不提供移出。被移出者停止房間輪詢、清除失效身份並顯示重新加入說明。若持邀請直接回來，先驗證舊身份再顯示加入表單，避免卡在無效座位。
- 房主一鍵分享：支援 Web Share API 時開原生分享面板，否則改為複製；剪貼簿失敗時提供手動複製。
- 房間邀請有效 24 小時，房主可撤銷並產生新連結。開局與結束後仍保留邀請管理，供其他朋友加入觀戰、再進行賽後復盤。
- 原邀請保存在房主分頁的 sessionStorage。失去原邀請後可重新產生；已有的玩家與觀戰身分不受影響。

## 3. 玩家對局

上到下為輪次、維修進度、本輪揭牌數、行動者、自己的秘密、隊員暗牌與公開紀錄。

電腦版首頁、加入頁與等待室沿用可捲動的正常文件排版，保留原本字級與間距；等待室的房間身分和管理操作直接展開。兩款遊戲、觀戰與復盤才以視窗寬高配置分欄面板，主要操作在視窗內完成；長名單、規則與紀錄在所屬面板內查看。太空維修站寬螢幕從左到右為檢修紀錄、核心牌桌、可折疊秘密資訊與輪末確認；遊戲中的房間管理集中於選單。窄視窗或手機改回直向流式排版，保留可捲動與放大閱讀的能力。

加密通話的行動檔案也置於左側，與太空維修站共用紀錄欄寬；主要區域保留訊號牌、任務狀態、公開通話與同頻特務。每款遊戲的觀戰及復盤沿用同一組主畫面區域，可選擇查看的玩家；盲視角隱藏該玩家的身分、設備組成或訊號數字，上帝視角才使用伺服器回傳的已授權資訊，已公開的內容仍照常顯示。這些唯讀頁面不提供檢修、傳送、確認或投票操作。回放時間軸置於牌桌上方，分享及戰報工具透過展開面板使用，不縮窄整張牌桌。

- 秘密預設展開，只含自己的陣營與**目前剩餘設備組成**。可手動收起，確認任務資訊後不自動收合。內容佔用實際版面空間，不使用蓋住其他操作的浮動面板。揭牌後由伺服器扣除公開牌；種類數量總和等於剩餘暗牌數，每輪重新發牌後再更新。
- 自己的暗牌也只顯示背面與位置編號，玩家不取得任何未公開牌序。
- 切換分頁或移至背景時暫時收起秘密面板，返回時恢復原本的展開／收合選擇。這是使用便利性，不是防止同裝置他人查看的安全機制。
- 每輪全員確認新組成後，自動跳出維修模組宣稱數字；上限為全桌尚未翻出的維修模組數與自己的剩餘暗牌數兩者較小值，視窗顯示剩餘總數與上限。允許在範圍內說謊，全員提交後才可檢修。第一次點牌公開預選，再次點同一張牌開啟確認視窗，確認後由伺服器揭牌；已翻牌保留當輪原位。
- 尚未提交自己宣稱的玩家，只會收到其他人的「已宣稱／尚未宣稱」狀態，不會收到宣稱數字；提交後才顯示其他人的數量。觀戰與賽後復盤維持公開宣稱視角。
- 本輪檢修清單依實際揭牌順序排列，包含順序號、牌種、檢修者及持牌位置；最新事件在前的任務紀錄仍保留。反應爐危機數量、文字及牌面使用紅色。
- 新局在非終局的輪末保留原牌桌，強調最後翻開的設備，顯示確認人數及「已看清楚，準備下一輪」。每人只能確認自己，全員確認後才換輪；觀戰與復盤畫面僅顯示結算狀態。
- 每輪資訊確認及輪末結算期間，各玩家名字旁顯示「待準備／已準備」，分別依當輪資訊確認與輪末確認狀態更新。觀戰者不列入準備名單；復盤呈現當時狀態。
- 對局中沒有玩家的上帝視角切換；觀戰／復盤畫面與玩家操作元件分開。
- 首次同步使用繁中連線提示，持續中斷時提示檢查網路與伺服器，不定時重新整理整頁。已連線後若中斷，停用操作並自動重連。
- 牌桌標題旁與觀戰工具列提供音效開關。設備翻開與自己接手檢修使用不同短音；未獲播放許可時提示點選開啟，無音訊支援時保留文字提示。復盤不出現即時音效開關。

## 4. 結果與全站統計

- 結局後自動回原等待室，顯示上一局勝方、原因及歷史回放入口。新太空維修站對局會先保留結果與最後牌桌至少 8 秒，讓最後一張牌可被看見；勝負當下即成立。打開回放可查看陣營、進度及製作戰報；房間邀請保持有效，全員重新準備就可開始下一局。
- 房主可用「提前結束本局」及確認視窗中止對局，對話框明示不計勝敗。中止後回到等待室，顯示中止原因。
- 房間提供「離開房間」確認操作。主動離開會撤銷身份，其他分頁也失效；關閉或重新整理單一分頁則只影響該分頁的在線狀態。
- 首頁顯示全站完成局數、玩家參與人次，以及每款遊戲各陣營的勝／敗與勝率。
- 可展開各玩家人數的陣營勝利次數與結束原因。統計只計已結束對局，觀戰不計入參與人次；尚無對局時顯示空狀態。
- 第一款為兩陣營且無和局，陣營敗場為完成局數減勝場。若後續遊戲支援和局或多方共同勝利，需擴充統計契約與顯示方式。

## 5. 即時觀戰

- 等待室、玩家對局及觀戰畫面均可查看同一份觀戰席名單；自己是玩家時不標示為觀戰者。
- 觀戰以 HTTP 定期取得唯讀快照，不建立玩家 boardgame.io 連線，也不接收任何 moves。
- 預設盲視角：只見公開進度、行動者、剩餘暗牌數與已公開紀錄。結束前不顯示陣營、私人組成或暗牌順序。
- 上帝視角：顯示各隊員陣營、剩餘組成，以及每個位置的完整牌面。畫面持續提醒這包含秘密，觀戰時勿向正在遊玩的朋友透露。
- 切視角時先顯示讀取狀態，再呈現對應資料，避免把上帝內容暫時標成盲視角。禁止用 CSS 隱藏秘密充當資料過濾；過濾由伺服器執行。
- 這是朋友互信模式；已獲觀戰上帝視角的人能掌握秘密，無法靠介面防止私下串通。

## 6. 逐步復盤、分享與戰報

- 對局結束後，玩家與觀戰者皆可開啟復盤，使用上一／下一步、時間軸、自動播放／暫停，以及盲／上帝視角。
- 視角切換保留選定步驟。自動播放每 1.8 秒前進一次，到結尾暫停；拖動或按前後即停播。復盤是獨立唯讀快照，不會呼叫任何遊戲操作或改變線上對局。
- 若舊局 `complete=false`，明確顯示沒有完整逐步回放，不用最後狀態拼造歷史。若仍有最後狀態，可製作該狀態的戰報圖。
- 「分享這一步」建立獨立、7 天有效的公開唯讀連結。分享前明示選定步驟與視角，**上帝分享會公開整局的陣營與牌面**，收件人可前後查看整局。
- 公開路徑為 `/replay/{roomId}#share={token}`。進入後立刻移除 fragment、暫存 token；讀取時只在 `X-Replay-Token` 標頭傳送。
- 收件人從發行者選定步驟開始，視角固定，不具備加入房間、操作對局或再建立分享的權限，但可製作戰報圖片。
- 歷史回放及分享只呈現原局玩家，沒有目前觀戰名單或身分切換操作。
- 房主可撤銷房間所有對局的既有復盤分享。撤銷連結不能收回已下載或轉傳的圖片。
- 戰報在本機 Canvas 繪製原創太空風格 PNG，包含公開最近揭牌、玩家暱稱、目標、牌種、輪次、步驟、維修進度與當步結果。沒有外部圖檔或字體，不含 URL、token、憑證或秘密牌面，即使來源為上帝視角也只取公開內容。
- 產生後先預覽，可下載 PNG；支援原生檔案分享時可直接分享圖片，否則下載。切換步驟後清除舊預覽，防止分享錯誤步驟。

## 7. 詳細規則

- `/rules` 提供遊戲規則總覽，`/rules/space-station` 與 `/rules/encrypted-call` 分別說明各遊戲的完整規則；直接開啟或重新整理皆可讀取，不需要房間憑證。
- 首頁與房間頂部提供「詳細規則」，等待室的任務簡報另有完整規則連結。房間中開啟規則會另開分頁，避免離開目前的牌桌；尚未選擇遊戲時前往總覽。
- 規則頁維持可捲動排版，桌面提供章節導覽，手機換成單欄。內容包含人數、配置、每輪流程、行動、勝敗、補給與房間共通操作；不載入任何進行中對局的秘密資訊。

## 新增遊戲的接口

`src/client/game-registry.tsx` 為每款遊戲註冊玩家 Client、獨立唯讀 Snapshot、陣營與結束原因名稱。觀戰與復盤共用 Snapshot，只有玩家 Client 取得操作功能。

`BattleReport.tsx` 的 `posterRenderers` 可另外註冊該遊戲的原創 PNG 產生器。房間、邀請、統計外框、復盤時間軸與分享流程皆可重用。

## 邊界狀態

| 情境 | 畫面行為 |
| --- | --- |
| 邀請不完整、過期或撤銷 | 顯示錯誤，提示重開完整邀請或請房主更新 |
| 玩家已開局後才開邀請 | 玩家加入遭拒絕，可改選觀戰 |
| 加入時回應遺失 | 原分頁以相同 UUID 重試，恢復原身分 |
| 切換身分時回應遺失 | 保存同一次切換資料，按重試恢復結果，不重複占位 |
| 同瀏覽器其他分頁切換 | 畫面跟隨最新身分；舊身分的延遲回應不能覆寫它 |
| 玩家席位已滿 | 觀戰者仍可留在房內，等待空位後再切換 |
| 對局已開始 | 停用身分切換，說明返回等待室後開放 |
| 重新整理 | 使用此瀏覽器保存的原身分，不重複加入 |
| 清除網站資料或換瀏覽器 | 不能自動恢復原身分 |
| 舊局沒有完整回放 | 明確顯示不可完整逐步復盤，不假造資料 |
| 公開分享被撤銷或過期 | 顯示讀取失敗，不要求玩家憑證 |
| 原生分享／剪貼簿不支援 | 提供複製、手動複製或圖片下載 |

正式部署使用 HTTPS。不要加入會讀取網址、localStorage 或畫面的第三方分析／回放工具；座位與觀戰憑證不能放進分享訊息、公開紀錄或錯誤回報。
