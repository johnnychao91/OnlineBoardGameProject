# 手機版介面規格

直接開啟 [mobile-wireframes.html](./mobile-wireframes.html) 可檢視六個主要畫面與首頁統計示意。它使用內嵌 CSS 與假資料，不需要啟動服務、不會對外請求素材，也不會產生可用的邀請或憑證。設計基準為 390 px；窄螢幕可橫向捲動比較。

正式介面位於 `src/client/`。手機使用單欄，桌面把房間分享或對局紀錄移到側欄，支援至少 320 px 寬度。主要操作至少 44 px 高；深靛藍作底、薄荷青表示維修與可操作區、琥珀表示危機與秘密視角。狀態都有文字，不能只依靠顏色辨識。

## 1. 建立與加入

- 開房者選遊戲與暱稱，**不預選玩家人數**。頁面說明該遊戲可開始的人數範圍，第一款為 4～8 人。
- 開房密碼放在收合欄位，預設不儲存。可勾選「在這個瀏覽器記住」，成功開房後才儲存，下次自動帶入；可取消勾選或清除。共用裝置不建議記住。開房成功後，房主直接進等待室。
- 朋友開啟 `/join/{roomId}#invite={token}`，前端把 token 暫存目前分頁並立即從網址列移除，再選「參與遊戲」或「先來觀戰」並填暱稱。
- 玩家只在開局前加入；觀戰者不占座位、不計入開局人數，開局後仍可透過邀請加入。
- 同一瀏覽器同一房間只儲存一種身分。已加入時顯示「回到我的座位」或「回到觀戰席」，不重複加入，也不提供中途換身分。
- 玩家使用獨立座位憑證；觀戰者使用獨立觀戰憑證。兩種憑證都不會出現在邀請或公開復盤連結。
- 加入請求帶有暫存在當前分頁的 UUID；同邀請、同模式與 UUID 可安全重試，不會因回應遺失再占一席。成功後清掉邀請與 UUID；不同邀請重設 UUID，玩家／觀戰請求分開保存。

## 2. 等待與分享

- 等待室使用 HTTP 房間狀態，尚未掛載 boardgame.io 對局。名單只顯示已入座玩家，不預造固定人數的空位。
- 顯示目前玩家人數、人數上下限、已準備數與「已加入觀戰」人數。觀戰人數是持有有效觀戰身分的人數，不宣稱全部在線。
- 玩家按準備；4～8 位玩家且全員準備後，房主按「以目前 N 位隊員開始」。伺服器在此時鎖定本局實際人數。觀戰者不需準備。
- 房主可在其他玩家旁按「移出」，確認視窗列出暱稱並說明可用有效邀請重新加入；房主不可移出自己，開局後不提供移出。被移出者停止房間輪詢、清除失效身份並顯示重新加入說明。若持邀請直接回來，先驗證舊身份再顯示加入表單，避免卡在無效座位。
- 房主一鍵分享：支援 Web Share API 時開原生分享面板，否則改為複製；剪貼簿失敗時提供手動複製。
- 房間邀請有效 24 小時，房主可撤銷並產生新連結。開局與結束後仍保留邀請管理，供其他朋友加入觀戰、再進行賽後復盤。
- 原邀請保存在房主分頁的 sessionStorage。失去原邀請後可重新產生；已有的玩家與觀戰身分不受影響。

## 3. 玩家對局

上到下為輪次、維修進度、本輪揭牌數、行動者、自己的秘密、隊員暗牌與公開紀錄。

- 秘密預設收起，只含自己的陣營與**目前剩餘設備組成**。揭牌後由伺服器扣除公開牌；種類數量總和等於剩餘暗牌數，每輪重新發牌後再更新。
- 自己的暗牌也只顯示背面與位置編號，玩家不取得任何未公開牌序。
- 切換分頁或移至背景時收起秘密面板。這是使用便利性，不是防止同裝置他人查看的安全機制。
- 每輪全員確認新組成後，自動跳出維修模組宣稱數字；允許說謊，全員提交後才可檢修。第一次點牌公開預選，再次點同一張牌開啟確認視窗，確認後由伺服器揭牌；已翻牌保留當輪原位。
- 對局中沒有玩家的上帝視角切換；觀戰／復盤畫面與玩家操作元件分開。
- 首次同步使用繁中連線提示，持續中斷時提示檢查網路與伺服器，不定時重新整理整頁。已連線後若中斷，停用操作並自動重連。

## 4. 結果與全站統計

- 結局後自動回原等待室，顯示上一局勝方、原因及歷史回放入口。打開回放可查看陣營、進度及製作戰報；房間邀請保持有效，全員重新準備就可開始下一局。
- 房主可用「提前結束本局」及確認視窗中止對局，對話框明示不計勝敗。中止後回到等待室，顯示中止原因。
- 房間提供「離開房間」確認操作。主動離開會撤銷身份，其他分頁也失效；關閉或重新整理單一分頁則只影響該分頁的在線狀態。
- 首頁顯示全站完成局數、玩家參與人次，以及每款遊戲各陣營的勝／敗與勝率。
- 可展開各玩家人數的陣營勝利次數與結束原因。統計只計已結束對局，觀戰不計入參與人次；尚無對局時顯示空狀態。
- 第一款為兩陣營且無和局，陣營敗場為完成局數減勝場。若後續遊戲支援和局或多方共同勝利，需擴充統計契約與顯示方式。

## 5. 即時觀戰

- 觀戰以 HTTP 定期取得唯讀快照，不建立玩家 boardgame.io 連線，也不接收任何 moves。
- 預設盲視角：只見公開進度、行動者、剩餘暗牌數與已公開紀錄。結束前不顯示陣營、私人組成或暗牌順序。
- 上帝視角：顯示各隊員陣營、剩餘組成，以及每個位置的完整牌面。畫面持續提醒這包含秘密，觀戰時勿向正在遊玩的朋友透露。
- 切視角時先顯示讀取狀態，再呈現對應資料，避免把上帝內容暫時標成盲視角。禁止用 CSS 隱藏秘密充當資料過濾；過濾由伺服器執行。
- 這是朋友互信模式；已獲觀戰上帝視角的人能掌握秘密，無法靠介面防止私下串通。

## 6. 逐步復盤、分享與戰報

- 對局結束後，玩家與觀戰者皆可開啟復盤，使用上一／下一步、時間軸、自動播放／暫停，以及盲／上帝視角。
- 視角切換保留選定步驟。自動播放每 1.8 秒前進一次，到結尾暫停；拖動或按前後即停播。復盤是獨立唯讀快照，不會呼叫任何遊戲操作或改變線上對局。
- 若舊局 `complete=false`，明確顯示沒有完整逐步回放，不用最後狀態拼造歷史。若仍有最後狀態，可製作該狀態的戰報圖。
- 「分享這一步」建立獨立、7 天有效的公開唯讀連結。分享前明示選定步驟與視角，**上帝分享會公開整局的陣營與牌面**，收件人可前後查看整局。
- 公開路徑為 `/replay/{roomId}#share={token}`。進入後立刻移除 fragment、暫存 token；讀取時只在 `X-Replay-Token` 標頭傳送。
- 收件人從發行者選定步驟開始，視角固定，不具備加入房間、操作對局或再建立分享的權限，但可製作戰報圖片。
- 房主可撤銷這局所有復盤分享。撤銷連結不能收回已下載或轉傳的圖片。
- 戰報在本機 Canvas 繪製原創太空風格 PNG，包含公開最近揭牌、玩家暱稱、目標、牌種、輪次、步驟、維修進度與當步結果。沒有外部圖檔或字體，不含 URL、token、憑證或秘密牌面，即使來源為上帝視角也只取公開內容。
- 產生後先預覽，可下載 PNG；支援原生檔案分享時可直接分享圖片，否則下載。切換步驟後清除舊預覽，防止分享錯誤步驟。

## 新增遊戲的接口

`src/client/game-registry.tsx` 為每款遊戲註冊玩家 Client、獨立唯讀 Snapshot、陣營與結束原因名稱。觀戰與復盤共用 Snapshot，只有玩家 Client 取得操作功能。

`BattleReport.tsx` 的 `posterRenderers` 可另外註冊該遊戲的原創 PNG 產生器。房間、邀請、統計外框、復盤時間軸與分享流程皆可重用。

## 邊界狀態

| 情境 | 畫面行為 |
| --- | --- |
| 邀請不完整、過期或撤銷 | 顯示錯誤，提示重開完整邀請或請房主更新 |
| 玩家已開局後才開邀請 | 玩家加入遭拒絕，可改選觀戰 |
| 加入時回應遺失 | 原分頁以相同 UUID 重試，恢復原身分 |
| 重新整理 | 使用此瀏覽器保存的原身分，不重複加入 |
| 清除網站資料或換瀏覽器 | 不能自動恢復原身分 |
| 舊局沒有完整回放 | 明確顯示不可完整逐步復盤，不假造資料 |
| 公開分享被撤銷或過期 | 顯示讀取失敗，不要求玩家憑證 |
| 原生分享／剪貼簿不支援 | 提供複製、手動複製或圖片下載 |

正式部署使用 HTTPS。不要加入會讀取網址、localStorage 或畫面的第三方分析／回放工具；座位與觀戰憑證不能放進分享訊息、公開紀錄或錯誤回報。
