# 安全設計

本專案的範圍是朋友邀請制、單一伺服器的線上桌遊。玩家只能收到自己可見的遊戲資訊；伺服器仍持有完整狀態，因此具有主機或資料目錄存取權的人可以讀取秘密資料。本專案未實作讓伺服器管理者也無法讀取資訊的密碼學協定。

## 不同用途的憑證

| 類型 | 用途 | 保護方式 |
| --- | --- | --- |
| 建房密鑰 `CREATE_ROOM_KEY` | 允許建立新房間 | 正式環境必填至少 16 字元；由伺服器核對，不打包進前端 |
| 房間邀請 token | 允許加入特定房間 | 以加密安全亂數產生，放於邀請網址 fragment；有時效、可重設 |
| 座位憑證 | 證明目前瀏覽器對某座位或管理操作的權限 | 由伺服器產生並核對；玩家房主由 `hostPlayerID` 指定，不能把憑證放在分享連結 |
| 觀戰憑證 | 存取房間與唯讀觀戰；觀戰房主另有管理權 | 獨立身份，不占席；索引只保存雜湊，無玩家操作權限；管理時核對 `hostObserverID` |
| 回放分享 token | 存取指定終局歷史及指定視角 | 獨立亂數、雜湊保存、7 天到期、房主可整批撤銷；視角由伺服器鎖定，不能取得玩家或觀戰身份 |

建房密鑰只保護建房。它不是整站登入系統，也不會取代入房與每次操作的權限檢查。

管理者可把 `CREATE_ROOM_KEY` 改為自己容易記住的長密碼，正式環境仍要求至少 16 字元；建議使用多個隨機挑選的無關單字，避免姓名、網域或常見短密碼。只在 Git 外的私有環境設定中修改並重啟服務；變更不會撤銷既有房間的玩家憑證或邀請。

房號使用 12 bytes 的加密安全亂數產生，邀請 token 使用 32 bytes。隨機房號只是降低猜測機會，伺服器仍須檢查邀請與憑證，不能將知道房號當作已獲授權。

## 邀請生命週期

邀請預設 24 小時後到期，房主可在任何階段重設邀請以撤銷舊連結。開始遊戲後拒絕新玩家加入，但仍接受新觀戰者。重設邀請用來控制後續加入，不會撤銷既有玩家或觀戰憑證。房主權限由 `hostPlayerID` 指向的玩家憑證或 `hostObserverID` 指向的觀戰憑證驗證，沒有另外一組可分享的管理 token；第一任房主是座位 0。切換成觀戰仍保留房主資格，主動離開房間後才交接給其他玩家；一般觀戰者不會自動取得管理權。

邀請到期會阻止新的入座與觀戰身份，不會讓已加入玩家或觀戰者自動登出，也不會刪除房間。目前沒有自動清理過期房間或舊對局的功能；既有身份憑證也沒有以 24 小時為期限自動失效的設計。

邀請 token 放在網址 `#` 後方的 fragment，可避免隨一般 HTTP 請求路徑直接送入存取日誌。前端在畫面渲染前讀取，暫存於該分頁的 `sessionStorage` 並立即清除網址 fragment；玩家提交暱稱後，再透過 POST 換取座位憑證並清除暫存的加入 token。fragment 仍可能被頁面腳本、瀏覽器歷史、截圖、剪貼簿或收件者取得，因此整條邀請連結應視為敏感資訊。

房間索引保存的是邀請 token、觀戰憑證與回放分享 token 的 SHA-256 雜湊；座位憑證則保存在遊戲 metadata 中。房主的入房邀請連結另保留於目前分頁的 `sessionStorage`，供邀請介面顯示；它不是座位憑證。

前端首次加入時用 `crypto.randomUUID()` 產生 `requestID`，保留在分頁的 `sessionStorage`，重試時沿用。伺服器用邀請 token 作為 HMAC-SHA-256 的金鑰，結合房號、身份類型與 `requestID` 產生固定憑證；玩家與觀戰使用不同的計算範圍，即使使用相同 UUID 也不共用憑證。若該憑證已加入，重送會回傳原座位或觀戰身份，不重複分配。未提供 `requestID` 的 API 呼叫則使用新隨機憑證，不保證冪等。

`inviteToken + requestID` 的組合等同該次成功加入後的身份權限，不能公開、共用或放入日誌。重試已成功的加入請求可以在邀請輪替、到期或開局後回到原身份；這是取回原請求的結果，並非讓失效邀請建立新身份。它不提供跨裝置或清除所有瀏覽器資料後的身份找回。成功保存身份後，前端會清除暫存加入 token 與 `requestID`。

房主可在開局前移出其他玩家。移出、開局與加入共用房間佇列；移出原子保存座位清除及已撤銷憑證雜湊，既有連線也停止輸出並斷開。重啟後舊憑證與原加入請求仍無法恢復該身份。此功能不是封鎖本人：使用有效邀請與新的加入請求仍可取得新座位。舊請求回傳 `ADMISSION_REMOVED` 時，前端清除該次請求識別碼，讓使用者自行決定是否再按加入，不自動重入。

公開名單中的 `membershipID` 是該房間及座位憑證的不可授權指紋，移出請求必須附上它，防止舊畫面誤移出已補上相同座位的新玩家。它不能取代玩家或房主憑證。開局前空缺不會使其他玩家改號；遊戲模組必須使用實際參與座位清單配牌及安排回合。

已認證成員可在等待室切換參與／觀戰，不必重新提供邀請。切換與準備、開局共用房間佇列，並核對畫面當時的對局 ID；開局後禁止切換，避免把已看過秘密的觀戰者加入同局。成功切換會換發憑證、撤銷原身分並關閉舊等待室 Socket，房主資格跟隨新身分原子更新，舊憑證不能再用來管理房間。房間、邀請、歷史及其他玩家的準備與憑證保留。

切換回應可由原身分憑證、原對局 ID、目標身分及同一 UUID 重取。伺服器保存來源與目標憑證的雜湊及這次操作紀錄，僅在目標身分仍有效時恢復相同結果；舊憑證不能發起另一個切換，已離開、被移出或再次切換的身分也不能恢復。原加入請求不會重新占位。發布新房間索引前先保存新等待室，索引寫入失敗時保留舊身分可用；此流程不宣稱具跨檔案斷電交易保證。

請勿將請求 body、完整邀請連結、座位憑證或房主憑證寫入日誌。HTTP 存取日誌與反向代理設定也需要檢查。

## 瀏覽器憑證與 XSS 邊界

目前版本將 bearer 類型的玩家與觀戰憑證保存在同源 `localStorage`，方便重新整理與斷線後回到同一身份。這些值可被同源 JavaScript 讀取；若網站發生 XSS，攻擊者可能竊取憑證並冒用該身份。

同一瀏覽器的同一房間共用身分，任一分頁切換後，其他分頁會跟隨新身分。前端在送出前保存待完成切換的原憑證與 UUID，以便重新整理後恢復遺失的回應；成功後清除待辦資料。這份資料具有原身分同等敏感性，不能分享。切換以 Web Locks 協調多分頁，需支援此功能的新版瀏覽器及 HTTPS／localhost；過期分頁回應不能覆寫另一分頁已保存的新身分。

開房者可主動勾選「在這個瀏覽器記住」。只有成功建立房間後，開房密碼才會存入同源 `localStorage`；預設不勾選，也不放入網址、房間邀請或日誌。取消勾選或按清除會立即刪除已儲存值，之後開房需重新輸入。這份記憶不會跨裝置同步，也不是加密保管庫；同源腳本與能使用該瀏覽器的人可能取得開房權限，共用裝置不應啟用。更改伺服器密碼後，舊記憶值不再有效，需重新輸入。

因此前端不載入外部第三方腳本，不將暱稱或其他玩家輸入直接作為 HTML 注入，並以同一來源提供前端、API 與 Socket.IO。這些措施降低風險，但不消除所有 XSS 風險。後續若需求提高，可另設計 HttpOnly session 與伺服器端座位綁定，不能只把現有 token 改成 cookie 就當作完成。

目前不提供換裝置、清除瀏覽器儲存後的座位取回流程。分享自己的儲存內容、座位憑證或瀏覽器設定檔，等同分享座位權限。共享電腦上的使用者應特別留意資料保留。

## 隱藏資訊與操作授權

進行中的上帝觀戰視角是本專案明確開放的功能：已持有效邀請取得觀戰身份的人，可查看全體參與者的角色與牌面。玩家本身的憑證不能取得此視角，觀戰憑證也不能用於玩家同步或操作；但一個人使用另一個瀏覽器加入觀戰，或觀戰者私下轉告秘密，無法靠本版無帳號身份設計阻止。這是朋友間的信任約定，不宣稱防止串通。

回放僅於終局開放，只有 `complete: true` 的完整歷史可建立分享；具玩家或觀戰身份的分享者可選盲視角或上帝視角。分享 token 的視角與起始步驟由伺服器保存；收件者無法用參數擴大權限。分享內容是整局歷史，指定步驟只決定開始觀看的位置。戰報 PNG 僅使用所選快照的公開操作、暱稱及進度，即使從上帝視角產生，也不把 token、網址或私有欄位畫進圖片。

回放 token 亦使用 URL fragment，前端立即清除並在該分頁保存，請求時使用專用標頭。房主可撤銷所有分享；已下載的回放資料或圖片無法收回。全站統計僅回傳彙總數字，不公開房間列表、姓名或個人戰績。

房間觀戰名單只對已認證房間成員提供 `{id,name}`，不附帶憑證或雜湊，也不聲稱名單中的人都在線。房間可連續開局，回放 token 固定綁定原對局 ID。房間歷史回放與公開分享只包含原局玩家名單與歷史，不附帶目前房主、觀戰名單、觀戰人數或後來對局的結果。已離席身份不能用舊憑證存取房間歷史；需要使用仍有效的邀請重新加入。正常完成的歷史可由目前房間成員查看，提前中止則不開放未完成局的秘密回放，也不計勝敗。

對局更換時，舊 Socket 會關閉，佇列在執行操作時再次核對對局 ID；封存檔案拒絕後續狀態及 metadata 更新。房主提前結束的確認視窗也綁定當時的對局，不能把過期確認套用到新局。全員離線由已認證的分頁心跳與玩家連線判定，公開分享收件者不能維持房間在線；主動離開會撤銷同一身份的所有分頁。

- 遊戲規則、回合與勝敗由伺服器裁定。客戶端傳送操作意圖，伺服器檢查操作者、目前階段、目標與參數。
- 進行中的玩家視角只含自己的角色、設備組成與公開資訊，排除其他人的秘密、所有暗牌順序及亂數資料；只在畫面上蓋住卡片並不足夠。
- 初次同步、重連同步、增量更新、操作紀錄、錯誤訊息與房間 API 都須維持各自的資訊範圍。觀戰與終局回放依獨立授權明確開放盲／上帝投影；這兩種 HTTP 輸出均不包含 metadata、亂數種子、plugins 或身份憑證。
- 不能透過未受保護的 boardgame.io 原始 Lobby／`games` API 繞過房間加入流程。
- Socket.IO 的身份檢查必須涵蓋同步與操作。`PUBLIC_ORIGIN` 的來源限制不是玩家驗證，也無法阻止自製程式直接發送請求。
- 正式頁面不應公開可以檢視完整內部狀態或改動遊戲狀態的開發面板。

## 主機、資料與公開儲存庫

Node.js 預設只監聽 `127.0.0.1`，對外由 Apache 提供 HTTPS。服務使用專用帳號，程式目錄與資料目錄分離；正式環境設定與完整資料只能由必要的管理者或服務帳號讀取。

自訂本機 JSON adapter 的對局檔包含隱藏狀態、完整逐步回放及憑證，房間索引也屬私有資料。回放與最新狀態寫在同一份檔案，重送版本不會重複追加；舊版缺少的歷史不補造。備份具同等敏感性，需限制權限；目前並未提供應用程式層的靜態資料加密。

儲存 adapter 只接受 16 字元 base64url 對局 ID，檔名不接受路徑分隔符、相對路徑或磁碟代號。檔內對局識別碼必須精確符合請求，避免 Windows 大小寫別名誤讀或誤刪其他對局。程式拒絕資料目錄位於前端靜態目錄內的配置，但管理者仍應避免另外把資料或備份放到 Apache 公開目錄。

公開儲存庫只放程式、文件與不含密鑰的範例。`.env`、`data`、備份、TLS 私鑰與執行日誌都不應提交。公開前應檢查完整 Git 歷史；刪除最新版本中的密鑰不會清除舊提交。若真實密鑰曾外洩，必須撤銷或更換，不能只刪除檔案。

實際站點身份也不屬於公開專案內容。網域、公開 IP、DNS／憑證名稱只留在主機的私有配置，文件與部署範本使用 `example.com` 等保留示範網域。先把範本複製到 `/etc` 再修改，不在 Git 內保存實際環境的對照表。

`npm run check:public` 掃描目前已追蹤的工作檔案，檢查非示範站點、常見 token／私鑰及私有檔名；CI 會執行同一檢查。外部文件與 npm metadata 主機採明確允許清單。這是防止誤提交的檢查，不是完整秘密掃描器；它不掃 Git 舊歷史或圖片像素，也不能證明沒有任何形式的敏感資訊。新增圖片仍須目視確認，發布前另檢查全部歷史。不要為了讓正式網域通過而把它加入公開允許清單。

遊戲素材與依賴套件各有授權條件。新增圖像、字型、音效與程式碼時，保留來源及授權資料；原創主題本身不會替第三方素材取得授權。

## 尚未涵蓋的能力

每個房間可連續遊玩，各局使用獨立對局 ID。沒有開局後由房主移出玩家、永久封鎖、將角色交給另一個人、跨裝置找回或正式身份帳號 API。主動離開會撤銷原憑證；重新加入需要有效邀請，且參與者只能在等待室加入。

此版本未承諾公開大型服務所需的完整帳號系統、多因素驗證、跨裝置身份恢復、防阻斷服務能力或多機容錯。正式上線前，依實際程式與部署結果驗證請求限制、錯誤處理、依賴修補及資料保留策略。需要擴大開放範圍時，應先補足這些設計與驗收。

若發現漏洞，請私下聯絡儲存庫擁有者並提供可重現步驟；不要在公開 issue 中貼上正在使用的邀請、憑證、個人資料或私有伺服器設定。
